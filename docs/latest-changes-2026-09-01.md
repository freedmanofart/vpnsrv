# Последние изменения — 1 сентября 2026

Документ описывает изменения из коммитов `f421fc8`, `5d45970` и `783bb69`,
их пользовательское поведение, хранение данных, развёртывание и проверки.

## Публичный сайт

Верхняя часть лендинга перенесена из `freedom-vpn-mockup-v3.html`:

- белая навигация с переходами к возможностям, тарифам и кабинету;
- адаптивный тёмно-синий hero-блок;
- карточка-предпросмотр подключения;
- кнопки «Подключить» и «Выбрать подписку»;
- мобильная раскладка для ширины до 850 и 520 пикселей.

Кнопки подключения больше не выбирают первый тариф автоматически. Они открывают
модальное окно с тремя группами: «Лайт», «Стандарт» и «Ультра». В каждой группе
показываются доступные периоды и цены. Пока пользователь не выбрал конкретную
подписку, отправка формы блокируется.

На лендинге остаются только активные публичные планы длительностью 30 дней.
Значения берутся из `plans`; HTML не содержит отдельной копии цен. Выбранный
`plan_id` передаётся в `POST /web/register` и повторно проверяется API.

## Вход в web-кабинет

На `/cabinet` доступны два реально работающих режима:

1. «Код из письма» вызывает `POST /web/register`. API отправляет одноразовую
   ссылку, а в PostgreSQL хранит только SHA-256-хеш токена.
2. «Пароль» вызывает `POST /web/password/login`. При успехе API создаёт новый
   `cabinet_access_tokens`, устанавливает `HttpOnly`, `SameSite=Strict` cookie
   и возвращает успешный JSON-ответ.

Переключатель меняет активную половину, поясняющий текст, поле пароля и основную
кнопку без перезагрузки страницы. «Забыли пароль?» запускает проверенный
email-сценарий и не раскрывает сохранённый пароль.

После первого перехода по подтверждённой email-ссылке пользователь без пароля
перенаправляется на `/cabinet/password`. Там пароль можно создать либо отложить
настройку и открыть кабинет. Сохранение выполняет `POST /web/password`, который
требует действующую защищённую cookie.

Пароль никогда не сохраняется открытым текстом. `app.core.security` использует
PBKDF2-HMAC-SHA256, индивидуальную 16-байтовую соль и 600 000 итераций. Сравнение
хешей выполняется constant-time функцией `secrets.compare_digest`.

Миграция `b74e2c31a190` добавляет nullable-колонку `users.password_hash`. Поэтому
существующие пользователи продолжают входить по письму и могут создать пароль
после следующего подтверждённого перехода. Откат миграции удаляет только эту
колонку; email-вход остаётся работоспособным.

### Публичные маршруты аутентификации

| Метод | Маршрут | Назначение |
|---|---|---|
| `POST` | `/web/register` | Создать/найти пользователя и отправить magic-link |
| `GET` | `/cabinet/access/{token}` | Проверить ссылку и установить cookie |
| `POST` | `/web/password/login` | Проверить email и пароль, создать сессию |
| `GET` | `/cabinet/password` | Показать настройку пароля авторизованному пользователю |
| `POST` | `/web/password` | Сохранить новый пароль авторизованному пользователю |
| `POST` | `/cabinet/logout` | Удалить cookie кабинета |

Страницы кабинета отправляют `Cache-Control: no-store`, CSP, запрет frame и
`Referrer-Policy: no-referrer`. При HTTPS cookie дополнительно получает
`Secure`. Ошибка парольного входа не уточняет, существует ли email.

## Покупка и кабинет

На лендинге и в кабинете планы сгруппированы по верхнему уровню тарифа. Выбор
страны из web-интерфейса удалён: API использует активную ноду текущего клиента,
а при её отсутствии — первую активную ноду. Способ оплаты и загрузка чека
остались без изменений.

Одна подписка может иметь несколько исторических платежей. Ограничение unique
на `payments.subscription_id` заменено обычным индексом миграцией
`a6d9274f1c03`. При сбое фиксации продления компенсация восстанавливает прежнего
клиента 3x-ui, а не оставляет пользователя без доступа.

## Почта, публикация и сертификаты

Публичный адрес текущего стенда — `https://fedora.taile485ac.ts.net`. Tailscale
Funnel проксирует его на `127.0.0.1:8000`; API не открывает порт напрямую во
внешнюю сеть. Postfix слушает только loopback и Docker bridge и используется
API через `host.docker.internal:25`.

`scripts/renew_tailscale_cert.sh` атомарно обновляет файловый сертификат для
внешних listeners. Таймер `vpn-tailscale-cert.timer` запускает проверку
еженедельно. Сам Funnel получает и продлевает сертификат автоматически.

## Развёртывание

Обязательный порядок для версии `783bb69` и новее:

```bash
git pull --ff-only origin newnode
docker compose build api bot
docker compose run --rm api alembic upgrade head
docker compose up -d --force-recreate api bot
```

Проверки после запуска:

```bash
docker compose run --rm api alembic current
curl -fsS http://127.0.0.1:8000/health
curl -fsS https://fedora.taile485ac.ts.net/
docker compose ps api bot worker
docker compose logs --tail=100 api bot worker
tailscale funnel status
systemctl is-active postfix vpn-tailscale-cert.timer
```

Ожидаемая миграция: `b74e2c31a190 (head)`. `/cabinet` без cookie намеренно
возвращает `401` вместе с HTML-формой входа — это не ошибка health-check.

## Проверки разработки

Перед коммитом выполнены:

```bash
.venv/bin/python -m compileall -q api/app bot/app
.venv/bin/alembic heads
.venv/bin/python -m unittest discover -s tests -p 'test_*.py'
git diff --check
```

Тестовый набор содержит 40 тестов. Добавленный сценарий проверяет создание
пароля после magic-link, успешный парольный вход, cookie-сессию и отказ при
неверном пароле. Лендинг и оба состояния переключателя проверены локальным
браузерным рендером.
