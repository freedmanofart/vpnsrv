# Обзор кодовой базы и предложения по упрощению

Срез выполнен 17 октября 2026 года по исходникам приложения, миграциям,
скриптам, контейнерным файлам и документации. Это обзор устройства и
приоритетов, а не отчёт о полном выполнении тестового набора.

## Структура

| Путь | Ответственность |
| --- | --- |
| `api/app/api/routes/` | HTTP API: кабинет администратора, web, бот и клиентские интеграции |
| `api/app/services/` | биллинг, уведомления, VPN provisioning, 3x-ui и синхронизация |
| `api/app/db/models/` | SQLAlchemy-модели прикладной PostgreSQL базы |
| `api/app/schemas/` | валидация запросов и ответов API |
| `bot/app/` | Telegram UX, тексты и обработчики aiogram |
| `alembic/versions/` | последовательные обновления схемы БД |
| `scripts/`, `deploy/` | обслуживание master и 3x-ui child-нод |
| `tests/` | регрессионные тесты API, биллинга и внешних интеграций |
| `deploy/node-image/` | воспроизводимый Docker-образ следующей 3x-ui-ноды с KIT |

Приложение состоит из API, Telegram-бота и фонового worker. Они разделяют
PostgreSQL и слой сервисов, но имеют разные пользовательские интерфейсы. Сетевая
топология и путь выдачи профилей описаны в [архитектуре](architecture.md).

## Приоритеты

### P1: разделить крупные HTTP-модули

`api/app/api/routes/admin.py`, `client.py` и `web.py` содержат соответственно
около 2 000, 1 460 и 1 390 строк; `bot/app/main.py` — около 2 860 строк.
Внутри этих файлов уже сосуществуют несколько независимых сценариев. При
следующих функциональных изменениях выделять роутеры/обработчики по предметной
области: операции и документация администратора; профили и импорт клиента;
вход, кабинет и оплата; состояния и платежи бота. Перемещать функции постепенно,
сохраняя маршруты и контракты API.

### P1: вынести HTML и браузерный код кабинета

`api/app/api/routes/web.py` хранит большие HTML/CSS/JS фрагменты рядом с
обработчиками HTTP. Это усложняет чтение, review и тестирование интерфейса.
Выделить шаблоны и статические ресурсы, сохранив серверную подстановку данных и
текущие security headers; сначала добавить точечные тесты рендеринга и
аутентификации, затем переносить без изменения UX.

### P1: сделать миграции единственным источником эволюции схемы

В проекте есть отдельные модели и Alembic-цепочка; важные ограничения должны
появляться в обоих местах. Для CI полезна проверка, что metadata моделей не
расходится с последней миграцией, плюс тест upgrade на пустой базе и upgrade с
предыдущей поддерживаемой версии. Не переписывать исторические production-
миграции: исправления оформлять новыми.

### P2: унифицировать обращения к внешним сервисам

Бот и API имеют независимые сценарии оплаты, уведомлений и provisioning.
Проверить, что повторы webhook, тайм-ауты 3x-ui и частичный отказ после списания
обрабатываются одинаково. Для каждого интеграционного вызова зафиксировать
тайм-аут, идемпотентность и безопасное журналирование; вынести повторы в общий
сервис только там, где реально повторяется одинаковая политика.

### P2: сократить ручную эксплуатационную поверхность

`scripts/` и `deploy/` содержат связанные с несколькими серверами сценарии
обслуживания. Добавить для каждого скрипта краткую таблицу: целевой узел,
предварительные условия, резервная копия, проверка результата и rollback.
Секреты, адреса панелей и клиентские идентификаторы не должны попадать в
документацию или диагностический вывод.

### P3: привести документацию к единой навигации

`docs/README.md` служит единым индексом; корневой `README.md` ведёт к нему.
Архитектура, жизненный цикл VPN, web-кабинет,
уведомления, база данных и эксплуатация имеют отдельные документы. Исторические
релизные заметки помечены архивом и не перечисляются в текущей документации
админки. При изменении топологии обновлять `docs/architecture.md`, а не
дублировать описание в датированных заметках.

## KIT и обновления поставщика

В текущем образе закреплены панельный fork commit
`95f19b192f477b59cc368dcb7751bcf2e0180e5b`, KIT CLI с локальными правками для
ручного AmneziaWG 3.1 и проверенная копия `kit-sub.py` KIT 1.2 по SHA-256.
Установленные child-ноды используют тот же выпуск; таймеры unattended update
выключены.

На дату проверки upstream уже выпустил [KIT 1.2.1](https://github.com/itsnotkubrick/3X-UI_KIT/releases/tag/v1.2.1) (14 октября). В сравнении с
1.2 изменения затрагивают примерно тысячу строк CLI и меняют ключ проверки
подписанных обновлений; среди добавленного есть команда полного удаления
установки. Поэтому 1.2.1 не подмешан в образ и не запущен на рабочих нодах.
Обновление нужно провести отдельным проверяемым проходом с анализом diff,
контрольной суммой исходников, резервными копиями и тестом на отдельной ноде.
Наличие нового выпуска не является основанием запускать его установщик на
production автоматически.

## Что требует отдельного этапа

Не объединять API- и bot-контейнеры и не переписывать крупные модули только ради
уменьшения числа файлов. Перед реорганизацией сначала зафиксировать основные
контракты интеграционными тестами, затем переносить небольшими изменениями.
Полный тестовый набор и статический анализ в рамках этого обзорного прохода не
запускались.
