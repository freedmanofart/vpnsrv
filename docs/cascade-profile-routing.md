# Каскадные профили через российскую ноду

Документ описывает целевую схему профилей и проверки, которые нужно выполнить
до публикации профилей для пользователей. Перечень не означает, что все
указанные входящие подключения уже созданы. Источник истины — главная панель
3x-ui; перед изменением подписок сверьте действующие ID входящих подключений и
их синхронизацию с дочерней нодой.

## Схема

```text
client -> 176.108.250.142:443 -> RU child inbound -> country-specific outbound
                                               -> US / PL / FI / CH upstream -> internet
```

Существующие прямые профили Швеции и канал управления между главной и дочерней
нодами должны остаться без изменений. Клиентские подключения через Россию — это
отдельные входящие подключения, назначенные российской дочерней ноде. Для
нескольких TCP-подключений на публичном порту 443 действующий мультиплексор SNI
должен направлять каждый уникальный SNI Reality на отдельный локальный порт.
Не открывайте эти локальные порты наружу и не занимайте порт, уже используемый
панелью, сайтом или другим транспортом. UDP-профили в эту схему TCP/443 не
входят.

Каждый клиентский профиль подключается к публичному адресу российской ноды.
Страна выхода определяется тегом входящего подключения на российской ноде, а
не адресом зарубежного сервера в URI клиента.

## Матрица профилей

| Название профиля | Транспорт клиентского подключения | Страна выхода |
|---|---|---|
| `🇺🇸 США (Reality)` | VLESS Reality/TCP | США |
| `🇺🇸 США (xHTTP)` | VLESS xHTTP + Reality | США |
| `🇺🇸 США (gRPC)` | VLESS gRPC + Reality | США |
| `🇵🇱 Польша (Reality)` | VLESS Reality/TCP | Польша |
| `🇵🇱 Польша (xHTTP)` | VLESS xHTTP + Reality | Польша |
| `🇵🇱 Польша (gRPC)` | VLESS gRPC + Reality | Польша |
| `🇫🇮 Финляндия (Reality)` | VLESS Reality/TCP | Финляндия |
| `🇫🇮 Финляндия (xHTTP)` | VLESS xHTTP + Reality | Финляндия |
| `🇫🇮 Финляндия (gRPC)` | VLESS gRPC + Reality | Финляндия |
| `🇨🇭 Швейцария (Reality)` | VLESS Reality/TCP | Швейцария |

Протокол в скобках обозначает фактический транспорт клиентского подключения.
Все профили одной страны используют один и тот же выход через эту страну.
Переданный сервер Финляндии задан URI xHTTP + Reality, поэтому он может быть
исходящим маршрутом для всех трёх финских профилей. Само наличие этого URI не
подтверждает существование отдельных серверов Reality или gRPC.

## Главная нода, пользователи и подписки

1. Создайте резервную копию базы главной ноды и конфигурации Xray/3x-ui
   дочерней ноды.
2. Создайте каждое новое входящее подключение через API главной ноды и назначьте
   его российской дочерней ноде. Используйте уникальные тег, ключ и короткий ID
   Reality, SNI и локальный порт прослушивания. Уже существующий профиль страны
   Reality можно повторно использовать только после проверки его активного
   подключения и маршрута; дубликат не создавайте.
3. Добавьте ID новых входящих подключений в `kit_inbound_ids` логической ноды
   RU. Не меняйте существующий основной `inbound_tag` и конфигурацию Швеции.
4. Добавьте каждого активного клиента во все новые входящие подключения с
   помощью существующего процесса `/vpn/nodes/{id}/reconcile`. При создании и
   продлении подключения должны сохраняться единые для всех профилей
   идентификатор `vpn-<client_id>`, срок действия, квота и ограничение числа
   соединений.
5. Включите `kit_subscription_all_clients=true` для всех активных пользователей
   либо перечислите нужные ID в `kit_subscription_client_ids`. Подписка KIT
   считается многопрофильной, только если 3x-ui возвращает для клиента не менее
   двух входящих подключений.
6. В комментариях к входящим подключениям указывайте страну и транспорт
   (`US-XHTTP`, `PL-gRPC`, `FI-REALITY`). Сопоставьте эти обозначения с точными
   подписями в `alternate_profile_labels`. API должен сохранять одинаковые
   названия в Freedom VPN, Incy, QR-кодах и выборе профиля в веб-кабинете.

Значение `profile_id` должно быть уникальным для каждой конфигурации
подключения, а не только для ноды, протокола или порта. Несколько входящих
подключений VLESS gRPC могут использовать один публичный TCP-порт 443.
Дублирующиеся ссылки из KIT и API альтернативных профилей нужно объединять по
параметрам подключения, игнорируя только отображаемый фрагмент.

## Правила маршрутизации

Маршрутизируйте трафик по тегу активного входящего подключения на российской
ноде. Для каждого каскадного профиля применяйте правила в таком порядке:

1. Отклоняйте обращения к частным и зарезервированным адресам, если этого
   требуют действующие правила.
2. Направляйте домены из настроенного списка заблокированных в России через
   зарубежный выход соответствующего профиля.
3. Направляйте российские домены и `geoip:ru` напрямую.
4. Остальной трафик направляйте через зарубежный выход соответствующего
   профиля.

Правила должны применяться только к соответствующим входящим подключениям
каскада. Не заменяйте общий маршрут по умолчанию через Швецию и не меняйте
несвязанные подключения Швеции, панели, подписки или сайта. Для каждого выхода
проверьте российский домен, заблокированный домен и международный домен.

## Совместимость клиентов

Фильтрация транспортов должна опираться на поля URI, а не на отображаемое
название. Incy должен получать только поддерживаемые им форматы: неверная
подпись не должна приводить к тому, что неподдерживаемый URI пройдёт фильтр.
Freedom VPN и Incy должны получать полный набор совместимых профилей при
обновлении подписки. Для обновления не требуется выпускать новый VPN-ключ или
создавать нового платёжного клиента.

## Проверки перед включением

- Убедитесь, что ID новых входящих подключений созданы на главной ноде и
  назначены нужной российской дочерней ноде.
- Проверьте, что дочерняя нода синхронизировала их и проверка конфигурации Xray
  завершается успешно.
- Проверьте конфигурацию nginx stream и убедитесь, что каждый публичный SNI
  попадает на соответствующий локальный порт.
- Синхронизируйте активных клиентов; для каждого входящего подключения проверьте
  хотя бы одного существующего и одного недавно созданного клиента.
- Получите подписку KIT и ответы API профилей Freedom VPN/Incy. Каждый
  запрошенный вариант страны и транспорта должен встретиться ровно один раз, а
  URI должен использовать `176.108.250.142:443`.
- Подключитесь через каждый профиль и проверьте, что внешний IP соответствует
  выбранной стране. Убедитесь, что обращения к российским ресурсам идут
  напрямую, а прежний шведский профиль по-прежнему работает.
- Публикуйте новые профили для пользователей только после успешного завершения
  всех проверок.

## Текущее состояние развёртывания

Целевая матрица выше не подтверждает, что профили уже развёрнуты. Во время
проверки российской ноды без внесения изменений 19 октября 2026 года конфигурация
Xray прошла проверку, но действующая маршрутизация не соответствовала
требуемой схеме:

- присутствовали только исходящие маршруты `cascade-us-test` и
  `cascade-pl-test`; маршрута через Финляндию не было;
- подключения Reality `in-443-tcp` и `in-23691-tcp` направлялись на тестовые
  маршруты США/Польши, но для `in-443-tcp` одновременно действовали безусловные
  правила США и Польши; Xray применяет первое совпавшее правило, поэтому до
  второго дело не доходило;
- xHTTP (`in-8443-tcp`) и gRPC (`in-2083-tcp`) попадали под общее правило каскада
  через Швецию, а не под отдельные маршруты США, Польши или Финляндии.

Поэтому обновление подписки Incy не может добавить весь запрошенный набор
профилей: на сервере отсутствовали необходимые маршруты и выход через Финляндию.
Из SSH-сеанса российской ноды не удалось получить доступ к API главной ноды,
поэтому входящие подключения, маршрутизация и подписки пользователей не
изменялись. Не считайте целевую матрицу развёрнутой, пока не пройдены проверки
выше.

19 октября 2026 года переданный сервер Швейцарии VLESS Reality/TCP был проверен
с российской ноды через временное локальное SOCKS-подключение и отдельный процесс
Xray. Конфигурация Xray прошла проверку, запрос HTTPS через прокси завершился
успешно, внешний адрес был `94.26.35.10`. После проверки временные процесс и
файлы удалили. Это подтверждает доступность швейцарского сервера с российской
ноды, но не создаёт клиентское входящее подключение, маршрут через страну или
профиль подписки. Существующие маршруты и профили пользователей не менялись.

Позже, 19 октября 2026 года, был развёрнут отдельный профиль `CH-REALITY`; при
этом действующие подключения Швеции, США, Польши и Финляндии не меняли:

- входящее подключение главной ноды ID `37` (`n8-in-23692-tcp`) назначено
  российской дочерней ноде ID `8`;
- управляемый клиентский адрес опубликован на `176.108.250.142:443`; nginx по
  SNI `www.microsoft.com` направляет трафик на локальный порт `23692`;
- шаблон Xray дочерней ноды направляет домены, заблокированные в России, и
  трафик по умолчанию через `cascade-switzerland`, а российские домены и
  `geoip:ru` — напрямую;
- логическая российская нода включает подключение `37` в `kit_inbound_ids` и
  сопоставляет `CH-REALITY` с `🇨🇭 Швейцария`; синхронизация добавила всех пяти
  активных клиентов VLESS без изменения их UUID и тарифов;
- созданный профиль проверен под именем `🇨🇭 Швейцария (Reality)` на
  `176.108.250.142:443`. Полное подключение Reality через публичное входящее
  соединение дало внешний IP `94.26.35.10`; проверки конфигураций Xray и nginx
  прошли успешно.

Активная карта `stream` на российской ноде находится в
`/etc/nginx/kit-stream.conf`. Похожий файл `/etc/nginx/ru-kit-stream.conf` не
подключён к действующей конфигурации nginx.
