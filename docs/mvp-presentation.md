# Freedom VPN MVP

Презентационный обзор реализованной версии сервиса.

## Коротко

Freedom VPN MVP — это готовый к пилотной эксплуатации сервис продажи,
выдачи и сопровождения VPN-доступа. Пользователь может купить подписку через
Telegram или web-кабинет, получить VLESS Reality xHTTP ключ, управлять доступом
и продлевать услугу. Оператор управляет тарифами, платежами, пользователями,
VPN-нодами и диагностикой из единой web-админки.

Система построена вокруг собственного FastAPI backend, Telegram-бота,
PostgreSQL и панели 3x-ui, которая отвечает за Xray, inbound-конфигурации и
фактических VPN-клиентов.

## Ценность MVP

- Быстрый запуск продаж VPN-подписок без ручной выдачи ключей каждому клиенту.
- Единая коммерческая логика для Telegram, сайта, web-кабинета и админки.
- Автоматическая выдача, продление, перевыпуск и отзыв VPN-клиентов через 3x-ui.
- Поддержка ручных платежей и интеграции с Platega.
- Операторский интерфейс для поддержки, диагностики и управления доступом.
- Документированные сценарии деплоя, обслуживания, резервного копирования и
  добавления новых 3x-ui нод.

## Реализованные пользовательские сценарии

### Покупка через Telegram

Пользователь открывает бота, выбирает устройство, страну, тарифный пакет и срок.
После выбора способа оплаты бот создаёт платёж через VPN API. Для ручных
способов пользователь отправляет чек, для Platega получает ссылку или QR, а для
Telegram Stars используется нативный invoice flow.

После подтверждения платежа backend создаёт или продлевает подписку, выпускает
новый VPN-клиент в 3x-ui и возвращает пользователю ключ и QR-код.

### Покупка через сайт и web-кабинет

Публичный лендинг `/` показывает активные публичные тарифы из базы данных.
Кнопка подключения ведёт в checkout внутри web-кабинета.

В web-кабинете пользователь может:

- войти по одноразовому email-коду;
- войти по email и паролю;
- посмотреть статус подписки и остаток дней;
- увидеть текущий тариф, лимит трафика и число подключений;
- получить действующий VPN-ключ;
- скачать или открыть приложения для основных платформ;
- продлить текущую подписку;
- перейти на другой тариф;
- выбрать способ оплаты;
- загрузить чек для ручной оплаты;
- посмотреть последние платежи.

### Управление подпиской

Пользователь может запросить статус подписки в Telegram или открыть web-кабинет.
Система показывает только активный, не истёкший VPN-клиент. При продлении или
смене страны старый ключ отзывается, а новый выпускается с новым UUID.

### Промокоды и пробный доступ

В Telegram реализованы сценарии промокода и пробного доступа. Оператор может
одобрить пробный доступ через админский Telegram-чат; после одобрения
пользователь получает ограниченный по времени VPN-доступ.

### Поддержка и отзывы

Бот принимает обращения в поддержку и пересылает их в админский чат. Оператор
может ответить пользователю из Telegram. Также реализован сценарий сбора
отзыва и отправки его в канал отзывов.

## Реализованные административные возможности

Web admin доступен на `/admin` и защищён HTTP Basic Authentication. В текущем
MVP он является основной операторской точкой управления сервисом.

В админке реализованы разделы:

- `Health` — проверка API, PostgreSQL, публичного сайта, кабинета, админки,
  SMTP, SSL и 3x-ui нод.
- `Пакеты тарифов` — управление группами тарифов: Лайт, Стандарт, Ультра.
- `Тарифы` — создание, изменение, отключение и удаление тарифов.
- `VPN-ноды` — создание логических локаций, health check, reconcile и
  изменение статуса ноды.
- `Пользователи` — просмотр профилей, ручная выдача доступа, перевыпуск ключа,
  смена пароля, сброс пробного доступа.
- `Подписки` — просмотр и административное продление.
- `VPN-клиенты` — просмотр клиентов и отзыв активного доступа.
- `Платежи` — просмотр заказов, чеков, ручное подтверждение, отмена, ошибка,
  возврат.
- `Способы оплаты` — управление методами оплаты и QR-картинками.
- `Устройства` — активации клиентских устройств и отзыв токенов.
- `Коды входа` — последние email-коды web-кабинета для поддержки.
- `Email-логи` — история отправки писем.
- `Настройки` — email и Telegram chat ID для админских уведомлений.
- `Документация` — быстрые ссылки на эксплуатационные markdown-документы.
- `Скрипты` — безопасные проверки из API-контейнера и готовые host-only команды.
- `Инфраструктура` — публичные ссылки, API, кабинет, admin, 3x-ui master и
  backup targets.
- `Debug` и `Audit log` — диагностические сессии и журнал действий.

## Платежи

MVP поддерживает несколько типов оплаты:

- ручные банковские способы с загрузкой чека;
- Platega: СБП QR, карта МИР и криптовалюта при включении соответствующих
  методов у провайдера;
- Telegram Stars через invoice flow;
- mock/auto-confirm режим для разработки и тестов.

Платёж создаётся идемпотентно: повтор одного запроса с тем же ключом возвращает
существующий заказ и не создаёт дубль. Подтверждённый платёж создаёт новую
подписку или продлевает активную. Одна подписка может иметь несколько
исторических платежей.

Webhook Platega обрабатывается только после проверки заголовков провайдера.
Повторная доставка callback безопасна: события сохраняются в журнал
`payment_events` по уникальной паре `provider + event_id`.

## VPN provisioning

VPN API не управляет Xray напрямую. Он обращается к REST API 3x-ui master,
который уже управляет inbound и child-нодами.

При успешной оплате, продлении или перевыпуске backend:

1. выбирает активную логическую ноду и её VLESS Reality xHTTP inbound;
2. создаёт новую запись VPN-клиента в PostgreSQL;
3. добавляет клиента в 3x-ui с UUID, служебным email `vpn-<client_id>`,
   сроком действия, Telegram ID и лимитом одновременных IP;
4. формирует VLESS URI из общей конфигурации ноды и UUID клиента;
5. показывает ключ пользователю в Telegram, web-кабинете или админке.

При ошибках используются компенсационные операции: если клиент уже создан в
3x-ui, но транзакция в БД не завершилась, backend пытается удалить созданного
клиента из панели. При неуспешном продлении система также пытается вернуть
предыдущий рабочий ключ.

## Тарифная модель

Тарифы разделены на пакеты и конкретные сроки.

Пакеты:

- `Лайт` — 5 одновременных подключений/IP и 250 ГБ трафика.
- `Стандарт` — 15 одновременных подключений/IP и 650 ГБ трафика.
- `Ультра` — 30 одновременных подключений/IP и 3 ТБ трафика.

Конкретный план задаёт цену, валюту и длительность в днях. На сайте и в
кабинете показываются только активные публичные тарифы. Цена копируется в
платёж при создании заказа, поэтому последующие изменения тарифа не меняют
исторические платежи.

## Уведомления

Реализованы клиентские и админские уведомления.

Клиент получает:

- email-код для входа в web-кабинет;
- уведомление о скором окончании подписки;
- уведомление об окончании подписки;
- уведомление об успешной оплате Platega, если есть email или Telegram ID.

Администратор получает:

- уведомление о новой ручной покупке;
- чек, загруженный пользователем;
- уведомление об успешной оплате Platega;
- inline-кнопки для подтверждения, ошибки или отмены ручного платежа.

Повторные письма об окончании подписки защищены через `audit_logs`, чтобы
worker не отправлял одинаковое уведомление каждый цикл.

## Безопасность

В MVP уже реализованы базовые защитные механики:

- административная панель закрыта HTTP Basic;
- служебные API требуют Bearer token или admin Basic;
- web-кабинет использует `HttpOnly`, `SameSite=Strict` cookie;
- при HTTPS cookie получает флаг `Secure`;
- одноразовые email-коды ограничены сроком жизни и числом попыток;
- пароли хранятся как PBKDF2-HMAC-SHA256 hash с индивидуальной солью;
- страницы кабинета отдают `Cache-Control: no-store`, CSP, запрет iframe и
  `Referrer-Policy: no-referrer`;
- полные VLESS URI считаются секретом и не должны попадать в обычные логи;
- токены 3x-ui, Platega, SMTP и Telegram хранятся в окружении, а не в коде.

## Эксплуатация

Production-состав MVP:

- `vpn-api` — FastAPI backend;
- `vpn-bot` — Telegram bot на aiogram 3;
- `vpn-worker` — фоновые lifecycle и reconciliation задачи;
- `postgres` — внешняя PostgreSQL БД `vpn`;
- `3x-ui master` — панель управления Xray и child-нодами.

Операционная документация и скрипты покрывают:

- запуск и миграции Alembic;
- проверку health endpoints;
- проверку публичного сайта и API;
- диагностику SMTP;
- online-тесты ключевых API;
- backup, verify и restore PostgreSQL;
- проверку live-трафика VPN-клиента через 3x-ui `clientStats`;
- обновление Tailscale certificate master/site;
- обновление SSL child-нод;
- регистрацию новой 3x-ui ноды через идемпотентный скрипт.

## Что уже можно демонстрировать

1. Открыть публичный сайт и выбрать тариф.
2. Перейти в web-кабинет, запросить email-код и войти.
3. Создать заказ на продление или покупку.
4. Показать ручной платёж с загрузкой чека.
5. Показать Platega-flow: создание платежа, redirect/QR и обработка callback.
6. Открыть Telegram-бота и пройти покупку через выбор устройства, страны,

7. После оплаты показать ключ и QR-код.
8. В админке открыть пользователя, подписку, платёж и VPN-клиента.
9. Выполнить health check ноды и показать связь с 3x-ui.
10. Перевыпустить ключ или сменить страну с отзывом старого клиента.

## Текущие границы MVP

- Реальная сетевая часть делегирована 3x-ui; приложение не запускает свой Xray
  и не обращается к Xray gRPC.
- Лимит устройств реализован как `limitIp` в 3x-ui, то есть ограничение по
  одновременным исходным IP, а не строгая аппаратная регистрация устройства.
- `limitHwid` не используется, потому что для него нужен отдельный процесс
  регистрации устройств и совместимые клиенты.
- Health и scripts в админке запускают только безопасные allow-list проверки.
  Docker, systemd, SSH и backup/restore остаются host-only командами.
- FastAPI `/docs`, `/redoc` и `/openapi.json` сейчас публичны и должны быть
  закрыты на reverse proxy, если схему API нельзя показывать наружу.
- Выбор и ротация нод завязаны на корректную конфигурацию 3x-ui inbound и
  актуальные Reality/xHTTP параметры.

## Ближайшие улучшения после MVP

- Закрыть публичную OpenAPI-документацию на production reverse proxy.
- Доработать мониторинг и алерты вместо ручных health-проверок.
- Добавить операторское сравнение конкретного клиента в БД и 3x-ui перед
  исправлением рассинхронизации.
- Расширить аналитику платежей, retention, churn и загрузки нод.
- Добавить полноценный frontend как отдельное приложение, если server-rendered
  HTML перестанет хватать.
- Рассмотреть HWID-ограничения только после выбора поддерживаемых VPN-клиентов
  и понятного сценария сброса устройства.

## Итоговый статус

MVP закрывает полный цикл: привлечение пользователя, выбор тарифа, оплата,
выдача VPN-доступа, продление, перевыпуск, отзыв, уведомления и операторское
сопровождение. Сервис уже имеет рабочую основу для пилота и дальнейшей
продуктовой доработки: коммерческая логика находится в VPN API, сетевой слой
делегирован 3x-ui, а ключевые эксплуатационные сценарии оформлены в админке,
скриптах и документации.
