# Возможности VPN Admin на базе API 3x-ui

## Реализованный минимум

VPN Admin остаётся единственной точкой коммерческой логики, а 3x-ui отвечает
за inbound и сетевых клиентов. При создании, продлении или перевыпуске ключа
API отправляет в 3x-ui полный объект клиента с уникальным UUID, служебным email,
`expiryTime`, `tgId` и `limitIp`.

В тарифе задаются срок и число одновременных подключений:

| Вариант | `max_connections` в VPN API | `limitIp` в 3x-ui |
|---|---:|---:|
| Одно устройство/IP | 1 | 1 |
| До трёх устройств/IP | 3 | 3 |
| Без ограничения | 0 | 0 |

Ограничение считается 3x-ui по наблюдаемым IP и не гарантирует точного числа
физических устройств: несколько устройств за одним NAT могут выглядеть как
один IP, а мобильное устройство при смене сети — как разные IP. Поэтому в
названии тарифа корректнее писать «одновременных подключений/IP».

Изменение тарифа влияет на новые ключи. Уже выданный клиент хранит снимок
`max_connections`; для применения нового лимита его нужно безопасно
перевыпустить. Это исключает незаметное изменение условий действующего ключа.

## Управление платежами

Раздел «Платежи» позволяет обработать ожидающий платёж как `paid`, `failed` или
`cancelled`, а оплаченный — как `refunded`. Подтверждение создаёт подписку и
клиента тем же сервисом, что webhook; возврат отзывает клиента. Все действия
аудируются. Кнопки требуют повторного подтверждения в браузере.

## Следующие полезные функции OpenAPI 3x-ui

1. Показывать онлайн-состояние и последние IP клиента через client traffic/IP
   endpoints. Это диагностика, а не источник биллинга.
2. Добавить тарифный лимит трафика через `totalGB` и явную политику сброса.
   Сначала нужно определить, сбрасывается квота ежемесячно или на весь срок.
3. Дать оператору кнопку синхронизации одного клиента и сравнение полей БД с
   3x-ui перед исправлением расхождений.
4. Показывать фактически сгенерированные ссылки 3x-ui только администратору,
   сохраняя текущую маскировку секретов в логах.
5. Рассмотреть `limitHwid` лишь после выбора поддерживаемых приложений и сценария
   сброса зарегистрированного устройства.

Не следует отдавать браузеру учётные данные панели 3x-ui или вызывать её API
из JavaScript. Web admin обращается только к VPN API, а тот — к 3x-ui по своему
серверному токену.

## Оплата в Telegram

Сейчас бот показывает внешнюю ссылку/QR и создаёт платёж в VPN API при проверке.
Нативный Telegram Invoice требует отдельного режима:

- Telegram Stars (`XTR`) для цифровой услуги внутри Telegram; либо
- provider token подключённого Telegram-провайдера для поддерживаемой валюты.

Для реализации необходимо заранее выбрать режим, валюту и политику возвратов.
После выбора бот должен отправлять invoice, проверять `pre_checkout_query`, а
`successful_payment` передавать в VPN API как идемпотентное payment event.
До получения успешного события ключ создавать нельзя. Токен провайдера хранится
только в `.env` и не совпадает с логином панели 3x-ui.
